## Samenvatting

HA_MistralAI dekt alle vier de relevante HA-platforms en heeft een sterke TTS-streamingengine, maar is kwetsbaar in foutpaden en loopt achter op de HA-architectuur die de core-LLM-integraties sinds 2025 gebruiken. Het manifest claimde Platinum; in de praktijk werd Bronze niet gehaald.

Top-5 prioriteiten:

1. **Bugs die gebruikers direct merken** (MA-01 t/m MA-06, MA-09): kapotte TTS-stream als de eerste zin faalt, zoekantwoorden die uit de gespreksgeschiedenis verdwijnen, onafgevangen time-outs, een continue-conversation-schakelaar die niet uit kan.
2. **Wees-agents en datalek in web search** (MA-04): bij elke herstart een nieuwe Mistral-agent, soms met de volledige HA-prompt en entity-lijst als instructies.
3. **CI en release-hygiëne** (MA-08): geen automatische tests of hassfest, commits via web-upload, manifestversie liep achter op de releases.
4. **HA-native architectuur** (MA-10 t/m MA-12): `runtime_data`, een API-client, tests op echte HA-code en config subentries voor meerdere agents.
5. **Slimmere spraak** (MA-18 t/m MA-20): context biasing met huisnamen, camerabeelden in het gesprek en persoonlijk geheugen, geïnspireerd op Alexa+ en Gemini for Home.

### Kwaliteit en onderhoudbaarheid

- **Runtime-fouten:** een 401 tijdens gebruik start de reauth-flow niet; een 429 wordt niet opnieuw geprobeerd; de ruwe API-body belandt in de gesproken foutmelding (MA-07).
- **Duplicatie:** `_runtime`, `device_info`, statuscode-afhandeling en `ClientTimeout` staan vier keer herhaald (MA-10).
- **`hass.data` i.p.v. `entry.runtime_data`:** Bronze-regel `runtime-data` (MA-10).
- **Web-searchresultaten als `user`-bericht:** webinhoud krijgt gebruikersautoriteit in de prompt (prompt-injectie); alleen de eerste zoekvraag per beurt wordt gebruikt (MA-15).
- **Berichtconversie:** tekst naast tool calls gaat verloren; string-toolresultaten worden dubbel ge-JSON-encodeerd.
- **Sentence-splitter:** alleen Engelse afkortingen; geen flush bij lange zinnen zonder punt (MA-16).
- **Kleinigheden:** `data.get("choices", [{}])[0]` crasht op een lege lijst; `pcm_data += chunk` is kwadratisch; drie sets icoonbestanden.

## Analyse: featureset

| Platform | Wat er is | Wat ontbreekt t.o.v. HA en de Mistral API |
| --- | --- | --- |
| Conversation | Streaming, tool-loop (max 10), LLM API-selectie, Jinja-prompt, web search, continue conversation | Meerdere agents (subentries), attachments, web search als external tool, token-statistieken, dynamische modellijst |
| AI Task | Generate data, structured output, afbeelding-attachments | `GENERATE_IMAGE`, eigen model los van conversation, harde fout bij ongeldige JSON |
| STT | Voxtral batch, taal uit pipeline | Realtime via WebSocket, `context_bias` met huisnamen (max 100 termen), juiste talenlijst |
| TTS | Batch mp3 en gepipelinede WAV-streaming, voices dynamisch opgehaald | Eigen voices als default in de opties, voice cloning, juiste talenlijst |
| Integratie | Config flow, reauth, opties | Reconfigure flow, diagnostics, repair issues, vertaalde exceptions, meerdere API-keys |

`context_bias` is volgens Mistral geoptimaliseerd voor Engels en experimenteel voor andere talen; winst voor Nederlandse namen eerst meten.

## Analyse: oplossingen en architectuur

- **Eigen HTTP-laag i.p.v. SDK.** Licht en zonder requirements, maar SSE-parsing, retries en foutmapping zijn zelf gebouwd. Advies: een eigen `api.py`-client; de `mistralai`-SDK pas bij core-inclusie.
- **Web search via een synthetische functie-tool.** Terecht, want `web_search` werkt niet op `/chat/completions`. Maar drie routes (model, always, trigger), een persistente agent en een conversatiemap maken het complex. Advies: één route, stateless Conversations-call, resultaat als external tool call in de chat_log.
- **Eén config entry, één optieformulier met 12 velden.** De core-LLM-integraties gebruiken config subentries: per agent een eigen model, prompt en tools. `unique_id = DOMAIN` blokkeert een tweede API-key.
- **Pipelined TTS-streaming.** Het sterkste onderdeel: begrensde concurrency, volgorde behouden, nette cancel-afhandeling.
- **Tests met eigen HA-stubs.** Snel, maar tegen `MagicMock`s; de #36-regressie was hiermee niet te vangen. `pytest-homeassistant-custom-component` test tegen echte HA-code.
- **Releaseproces.** Commits via web-upload, geen CI, release notes in de README (opgelost in MA-08).
